# P1-B1: Storage (SQLite, Drizzle, repositories)

## Goal

All phase-1 state persists in one SQLite file behind the repository interfaces from `storage/types.ts`.

## Scope

**In:**
- Add Drizzle ORM and drizzle-kit to `@keith/core` with `bun add` (read the current Drizzle docs for the bun-sqlite driver first).
- Drizzle schema for every phase-1 table in storage.md, including `thread_participants`, `messages.author_person_id` (group-ready, I-2), `threads.slug` with its unique index, `persons.last_seen_at`, and the message tool-call and `ui` columns laid out in storage.md "Messages and tool calls".
- Migrations generated with drizzle-kit (never hand-written), plus `openDb(path)` that applies pragmas and migrations.
- FTS5 virtual table `memories_fts`, kept in sync by triggers, created in a migration (use drizzle-kit's custom migration feature for raw SQL).
- Repository implementations for every interface in `storage/types.ts`, including zod validation of JSON columns on read and `memories.search(text, filter)` with BM25 ranking.
- A test helper `createTestDb()` (temp file, auto-cleanup), exported for other lanes' tests from `storage/testing.ts`.

**Out:**
- Visibility logic (M1 passes a filter; storage only applies it as SQL conditions).
- Backups (phase 4).

## Acceptance criteria

- [x] Fresh DB → all migrations apply. Applying twice is a no-op.
- [x] Round-trip tests for each repository.
- [x] Messages page by `before` + `limit` in stable order.
- [x] `memories.search` finds by keyword and applies the `MemoryFilter` SQL exactly as storage.md specifies (table-driven test per filter field).
- [x] Assistant messages with `tool_calls` and tool messages round-trip into the shapes `LlmMessage` needs.
- [x] Data survives closing and reopening the DB file (S-3 groundwork).
- [x] No file outside `storage/` imports `bun:sqlite` or `drizzle-orm` (check-deps).
- [x] `bun run check` passes.

## Outcome

**Built** (all in `packages/core/src/storage/` unless noted):

- `schema.ts`: Drizzle schema for every phase-1 table in storage.md, including `thread_participants`, `messages.author_person_id`, the unique `(owner_person_id, slug)` index, `persons.last_seen_at`, and the message tool-call / `ui` columns.
- `packages/core/drizzle/`: two migrations generated by drizzle-kit: `20260926123942_init` (tables and indexes) and the custom migration `20260926123950_memories-fts` (FTS5 table `memories_fts`, backfill and three sync triggers; the SQL was written into the file drizzle-kit generated with `--custom`). `drizzle-kit check` and a re-run of `generate` report no drift.
- `packages/core/drizzle.config.ts`: a plain default-export object (no `defineConfig` import), so check-deps (R-4) stays green.
- `db.ts` / `index.ts`: `openDb(path)` sets WAL, `foreign_keys = ON`, `busy_timeout = 5000`, applies migrations and returns the `Db`.
- Repositories: `persons.ts` (persons, relationships), `access.ts` (auth tokens, nodes), `threads.ts`, `messages.ts`, `work.ts` (tasks, commitments, deliveries), `memories.ts` (CRUD, `search` with BM25, `list`), `plugin-data.ts`. JSON columns are parsed with zod on read (UI blocks with the protocol's `UiBlock` schema) and throw `STORAGE_CORRUPT` on a bad row (`orm.ts`).
- `testing.ts`: `createTestDb()` returns a migrated DB in a temp folder; `close()` (or `using`) deletes the folder. `fixtures.ts` holds ids and seed helpers for this folder's tests.
- Tests: 9 test files, round-trips for every repository, paging, role filter, `LlmMessage` replay shapes, a table-driven `MemoryFilter` test for both `search` and `list`, FTS sync on update/delete, migration idempotence, and S-3 reopen.

**Dependencies** (added with `bun add` in `packages/core`):

- `drizzle-orm` `1.0.0-rc.4` (exact) and dev `drizzle-kit` `1.0.0-rc.4` (exact). The current Drizzle docs install the `@rc` tag (v1), whose migrations are one folder per migration (`migration.sql` + `snapshot.json`, no `meta/_journal.json`). Docs read: https://orm.drizzle.team/docs/connect-bun-sqlite, https://orm.drizzle.team/docs/kit-custom-migrations, https://orm.drizzle.team/docs/drizzle-config-file, https://orm.drizzle.team/docs/migrations.
- `zod` `^4.6.5` (the version protocol and sdk already use).
- Biome nested config: https://biomejs.dev/guides/big-projects/.

**Decisions:**

- `memories_fts` stores its own copy of the content keyed by memory id instead of an external-content table: `memories` has a text primary key, and `VACUUM` may renumber implicit rowids, which would desync an external-content index. Deletes scan the FTS table by id, which is fine at household scale.
- Search text becomes quoted words joined with `OR` (FTS5 syntax in user text is never interpreted); ranking is `bm25()`, then `updated_at` desc, then id; default limit 8 (memory.md recall limit).
- The filter SQL omits branches that cannot match instead of binding booleans. It is logically equal to the storage.md SQL and covered by the table-driven test.
- `messages.page` with an unknown `before` returns an empty page; `commitments.resolve` and `deliveries.markDelivered` only change rows still `open`/`pending`; `pluginData.get` returns `undefined` for a missing key; unserializable plugin values throw `KeithError('INTERNAL')`. All recorded in storage.md.
- `node_id` columns have no foreign key (nodes are registered on `hello`, independently of tokens and messages).
- The migrations folder is found relative to `db.ts` (`../../drizzle`). A future compiled binary must ship that folder or embed the migrations.

**Deviations:**

- `packages/core/package.json` and `bun.lock` changed through `bun add` only (allowed by agent-workflow parallelism rules 4 and 5).
- `packages/core/drizzle/biome.json` (a nested Biome config, inside `owns`) turns Biome off for generated migrations, because drizzle-kit's `snapshot.json` formatting differs from Biome's and generated files must not be hand-edited. The root `biome.json` is unchanged.
- `drizzle.config.ts` uses a default export, which the tool requires (conventions allow default exports only for plugin entries).

**Follow-ups:**

- Other lanes import `createTestDb` from `storage/testing.ts` (a deep import that R-3 would normally disallow; the task names this path).
- `openDb` has no `AbortSignal` (R-10) because it is synchronous and the frozen `Db` interface has none.
