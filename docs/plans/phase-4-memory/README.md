# Phase 4: Memory + proactivity

**Goal:** Keith learns from conversations without being told, keeps long threads coherent, and reminds you of things on time. It delivers S-3 (semantic): a fact stated on day 1 is recalled on day 2 without the raw message in context. See [memory.md](../../architecture/memory.md) and [ADR-0014](../../decisions/0014-reflection-writes-conservative-inferred-memories.md) (proposed; P4-K1 starts once it is accepted).

The overview's lanes A–E map one to one. Lane S is new: two lanes (A/B and C) need storage changes, so one task owns the schema and migrations. The lanes test against fakes built from P4-K1's interfaces (agent-workflow parallelism rule 2).

## How the lanes connect

- **P4-K1** fixes everything that crosses a lane:
  - the `memory.reflected` / `thread.summarized` events;
  - the `rem` id prefix;
  - `[memory.reflect]`, `[memory.summary]`, `[mind.reminder]`;
  - `ThreadRecord` cursors, `RemindersRepository`, `messages.range` / `lastSeq`;
  - `Reflector`, `ThreadSummarizer`, `MemoryJob`, `ReminderService`;
  - the `reminder.set/list/cancel` specs;
  - `CoreSkillRegistry.registerDefault`;
  - the `backupDatabase` signature.

  Every broken implementer gets a placeholder in the same task (lesson from the [phase 0–3 audit](../phase-3-voice/hardening-audit.md)).
- **Reflection (A)** and **summaries (B)** are separate jobs (ADR-0014). Both use the existing `RunLoop` with `modelRole: 'utility'`, no tools, one step. Both run in the `background` lane. They share no code.
- **B** owns the context builder, so B also adds the one-line "load `morning_briefing`" hint for briefing turns. **D** owns the skill itself and the default-skill semantics.
- **C** needs no bootstrap change of its own: P4-K1 wires `fireDue` into `scheduling.start()` and registers the tools when `reminders` is passed. P4-I1 passes it.
- **Integration (I1)** is the only task that touches `bootstrap.ts`, `packages/core/test/**` and the root `package.json`. **I2** owns `tests/e2e/**`.
- Storage migrations are generated by drizzle-kit in P4-S1, never hand-written (R-18).

## Open decisions

| # | Decision | Where | Default in the plan |
|---|---|---|---|
| D1 | Visibility, merge and card rules for reflection | [ADR-0014](../../decisions/0014-reflection-writes-conservative-inferred-memories.md), **proposed** | Never wider than the conversation. Merge only within the same scope. Notes only, never tone |
| D2 | Summaries independent of reflection (memory.md said reflection updates the summary) | ADR-0014 | Independent, triggered by `turn.completed` |
| D3 | A third tool, `reminder.list` (the overview named only set/cancel) | P4-K1 | Added, or the model can't find an id to cancel |
| D4 | Reminder tools' `minTier` | P4-K1 | `member`, like `task.*` (they cause proactive messages) |
| D5 | Reminder timing: tick-driven, at-least-once | P4-C1 | Within one `scheduler.tickMs` (30 s). A crash can cause one duplicate, never a loss |
| D6 | A plugin skill with a default's name replaces it | P4-K1 (plugin-api.md) + P4-D1 | Replace, not `TOOL_NAME_TAKEN` |
| D7 | Backup format | P4-E1 | A plain folder with `manifest.json`; no archive dependency |
| D8 | `sqlite-vec` / embeddings | P4-A1 | Not planned. ADR-0015 only if the FTS recall corpus fails |
| D9 | New events | P4-K1 | `memory.reflected`, `thread.summarized`; no `reminder.*` events |

**Reserved ADR numbers:** `0014` for this plan (reflection rules; proposed with the plan, accepted before P4-K1). `0015` for P4-A1, only if FTS recall fails (sqlite-vec or embeddings). Lane agents start at `0016`.

**Exit:** S-3 (semantic) and the reminder e2e pass in CI, and a human ran the P4-I2 steps with a real model. No `> Planned (phase 4…)` marker is left in `docs/architecture`.
